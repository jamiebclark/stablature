## 2. Merge (`mergeRow`)

```ts
for (const field of SERVER_STAMPED_FIELDS[table] ?? []) {
  asRecord(merged)[field] = asRecord(local)[field] ?? asRecord(remote)[field] ?? null;
}
```

It runs after the mergeable-field loop, and only when `local` is defined. When `local` is undefined, `remote` is
taken whole, as today.

**Properties** (`src/lib/sync/__tests__/memo-merge.test.ts`, FR-100, SC-008):

- **M1, convergence**. Base memo `b` with recorder null. Four concurrent versions:
  - `e1`, label "Chorus feel" @ device A;
  - `e2`, label "Slower" @ device B, with a later clock;
  - `e3`, delete @ device C;
  - `e4`, the server's echo of `b`, stamped with recorder `u1` / "Sam", fields unchanged.

  All 24 orderings, each folded with `mergeRow` from `b`, give one row, deep-equal.
- **M2, idempotence**. Folding any edit twice equals folding it once, for each of `e1`–`e4`.
- **M3, commutativity, pairwise**. `merge(merge(b,x),y)` equals `merge(merge(b,y),x)` for all 12 ordered pairs.
- **M4, the stamp survives**. In every ordering of M1, the result's `recordedById === "u1"`.
- **M5, a patch cannot write the stamp**. `applyPatch("memos", row, { recordedById: "x" } as never, hlc)` throws.
- **M6, other tables are unchanged**. The existing `merge.test.ts` 24-ordering test passes unedited.

## 3. Push (server)

Additions to `applyPush` / `upsert`. Nothing else changes.

1. **Insert stamp.** If `name === "memos"` and there is no existing row: `values.recordedById = userId`,
   `values.recordedByName = await nameOf(userId)`. The name is read once per push, from `user.name`.
2. **Part check** before the upsert of a memo. If `select band_id from parts where id = row.partId` is missing, or
   differs from `row.bandId`, the row is rejected: `{ reason: "invalid", message: "That memo's part is not in that
   band." }`.
3. **Erase hooks** after the upsert:
   - `memos` with `merged.deletedAt !== null`: `eraseMemoAudio(tx, [id])`.
   - `memos` whose part is deleted: `eraseMemoAudio(tx, [id])`.
   - `parts` with `merged.deletedAt !== null`: `eraseMemoAudio(tx, select id from memos where part_id = $id)`.
4. `eraseMemoAudio(tx, ids)` is
   `insert … on conflict (memo_id) do update set bytes = null, sha256 = null, size = 0, erased_at = coalesce(memo_audio.erased_at, now())`.
   It is the only statement in the codebase that sets `bytes = null`. A grep check in `check:memo-fence` asserts that
   it appears exactly once.

Pull (`readPull`) is unchanged in code. It gains `memos` through `SYNCED_TABLES`, and never touches `memo_audio`.

## 4. Device: applying rows (`applyRemoteRows`)

Inside its existing single transaction, which now also spans `memoAudio`, `memoUploads`, `memoFetches`, `memoDrafts`
and `memoDraftChunks`:

- After a `memos` row merges with `deletedAt !== null`: `eraseLocalMemoAudio(database, [id])`. If this device holds a
  `band_full` refusal in that band: clear it.
- After a `parts` row merges with `deletedAt !== null`: `eraseLocalMemoAudio(database, ids of that part's memos)`.

## 5. Device: push rejections (`pushOnce`)

After a push response, for each `rejected` entry with `table === "memos"` and a reason in `read_only`, `unknown_band`
or `not_a_member`: set `memoUploads[id].refusal = { code: reason, message }` and `account = currentMemoAccount()`.
The outbox entry is still dropped, as today. The existing status message is still set, as today.

## 6. Device: the write path (`src/lib/local/memos.ts`, React-free)

| Function | Does, in one Dexie transaction |
|---|---|
| `saveMemo(draft, bytes, durationMs)` | `insertRow("memos", …)` (row + outbox); `memoAudio.put`; `memoUploads.put`; delete the draft and its chunks |
| `renameMemo(id, label)` | `patchRow("memos", id, { label: trimmed || null })` |
| `deleteMemo(id)` | `deleteRow("memos", id)` + `eraseLocalMemoAudio([id])` (+ clear same-band `band_full` refusals) |
| `deletePart(partId)` | `deleteRow("parts", partId)` + `deleteRow("memos", m)` for each of `liveMemos(partId)` + `eraseLocalMemoAudio(those)` |
| `liveMemos(partId)` | read: live memos of a part, by `recordedAt` then `id` (oldest first) |
| `retryMemo(id)` | clear the refusal / `memoFetches` backoff; `requeueRow("memos", id)` if `serverSeq === 0` |
| `setMemoAccount(userId)` | if it differs from `meta.memoAccount`: store it; `retryMemo` on every refused entry whose `account ≠ userId` |

`SongView`'s part-menu Delete calls `deletePart` **for every part**. With zero memos it writes exactly what
`deleteRow("parts", id)` writes today: the same row, and one outbox entry (INV-016's probe compares the dumps).
